# AGENTS.md

BoltMesh VPN — monorepo: FastAPI backend (`backend/`), React/Vite frontend in plain JS (`frontend/`), Flutter WireGuard client app (`client/`), Linux privileged helper (`client/linux/boltmeshd/`, Go, entry `cmd/boltmeshd/main.go`), Go node agent (`node-agent/`, entry `cmd/agentd/main.go`), AWS Terraform+Packer (`infra/aws`). Local dev stack is Podman Compose (`docker-compose.yml`).

## Commands

- **Full stack** (from repo root): `podman-compose up -d`. API `http://localhost:8000` (`/health` always; `/docs`+`/redoc` only when `APP_DEBUG=True`), frontend `:5173`, Postgres `:5432`, Redis `:6379`, regtest bitcoind/lightningd/monerod/monero-wallet-rpc.
- **Backend** (from `backend/`, always via `uv run`, Python 3.13): `uv run ruff check .` → `uv run ruff format --check .` → `uv run pyright` → `uv run lint-imports` → `uv run pytest`. CI (`.github/workflows/backend.yml`) runs all five, in that order.
- **Backend single test**: `uv run pytest app/billing/tests/test_lightning_gateway.py`. Tests live next to code (`app/<domain>/tests/test_*.py`, `testpaths=["app"]`, `asyncio_mode=auto`). `*_live.py` hits real Redis and self-skips if unreachable. Shared `FakeUnitOfWork`/mocks in `app/tests/conftest.py`.
- **Migrations**: run locally, NOT in the container (container user `appuser` can't write `alembic/versions/`): `cd backend && uv run alembic revision --autogenerate -m "..." && uv run alembic upgrade head`. In compose: `podman-compose exec backend alembic upgrade head`.
- **Frontend** (from `frontend/`): `npm run lint`, `npm run format` (CI checks with `format:check`), `npm test` (vitest, `src/**/*.test.{js,jsx}`), `npm run build`. Single alias `@` → `src/`, env vars must be `VITE_*`. No dev proxy — calls `VITE_API_URL`.
- **Client** (from `client/`, Flutter ≥3.47): `flutter analyze` → `dart format --set-exit-if-changed lib test` → `flutter test`. CI (`.github/workflows/client.yml`) runs all three in the `validate` job on every push/PR, plus `validate-android`/`validate-windows` jobs (`flutter build apk --debug` / `flutter build windows --debug`) that compile the Android app and the native Windows runner; Android (`appbundle`+`apk`), Linux installers (deb+rpm) and the Windows Inno Setup installer (all via `fastforge release --name=production`; each host runs only its own jobs) build only on `v*` tags; the Android artifacts are signed with the upload keystore when the `ANDROID_KEYSTORE`/`ANDROID_KEYSTORE_PASSWORD` secrets are set (`build-android` fails on a tag without them instead of shipping a debug-signed build), and the Windows artifacts are Authenticode-signed when the `WINDOWS_CERTIFICATE`/`WINDOWS_CERTIFICATE_PASSWORD` secrets are set (see `client/README.md`). Single test: `flutter test test/features/vpn/data/wg_conf_test.dart` (test paths mirror `lib/`). API base defaults to production (`https://api.boltmesh.mooo.com/v1`); point at a local stack with `--dart-define=API_BASE_URL=http://localhost:8000/v1` (plus `VPN_PROVIDER_BUNDLE_ID=` for the iOS/macOS Network Extension, `VPN_PLATFORM=` to override the `platform` enum). Run android app with `flutter run -d 127.0.0.1:5555` (android emulator is running on windows host tunneled through port 5555)
- **boltmeshd** (from `client/linux/boltmeshd/`, Go 1.26): `make vet`, `make test` (`go test ./... -v -count=1`), `make build` (amd64+arm64), `make all`; `make lint` needs golangci-lint v2. CI's `client.yml` `validate-boltmeshd` job runs `gofmt`, golangci-lint, `deadcode` and `go test ./...` on every push/PR. It is the privileged Linux helper (root, systemd socket `/run/boltmesh/boltmeshd.sock`, group `boltmesh`); the Flutter app talks to it over UDS and never runs `sudo`/`wg`/`wg-quick`. The deb/rpm stage it into the bundle via `hooks.pre` in `client/distribute_options.yaml` and install it from `postinstall_scripts`.
- **Node agent** (from `node-agent/`): `make vet`, `make test` (`go test ./... -v -count=1`), `make build` (amd64+arm64 to `bin/`), `make all` (= `clean`+`format`+`lint`+`vet`+`test`+`build`+`checksums`). `make generate` needs clang+libbpf headers — never part of `build`/CI. `make lint` needs golangci-lint v2 (v1 is EOL and can't target Go 1.26). CI's `validate` job runs on every push/PR (`gofmt -l`, golangci-lint, `deadcode`, `go test ./...`); the `build` job runs `make build` + `make checksums` (not `make all`) and verifies checksums only on `v*` tags.
- **Terraform** (from `infra/`): `make validate-all` (= fmt-check + validate dev/staging/minimal/global), `make tflint`. Targets take `ENV=` (default `dev`). CI uses `make init-validate-all` (init-no-backend + validate, no S3 backend needed); local `make validate-all` assumes already-inited envs.

## Conventions & gotchas

- **Backend layering** (`backend/pyproject.toml [tool.importlinter]`): routers → services → repositories; tier order `core < infrastructure < users < auth < {billing|subscriptions|vpn} < control_plane < admin` (top three piped = mutually independent; `control_plane`/`admin` are composition layers with no repositories of their own and may use everything below, nothing may reach up into them). Routers never touch repositories or ORM models; services never touch foreign repositories/sibling services (cross-domain only via ports in `core.interfaces`/`*/services/ports.py` + `Translated*` DI adapters with lazy imports in `*/dependencies.py`); repositories only map their own domain's ORM models (no cross-domain joins — compose via ports at the service layer); `app.tasks` never touches domain repositories or router schemas (only the infrastructure-owned email outbox, a delivery mechanism rather than domain state). `app/tests/conftest.py` resolves repos via `importlib` so it doesn't become a lint hub.
- **Cross-domain FKs are scalar UUID columns, no ORM joins** (e.g. `Invoice.user_id`, `Subscription.user_id`, `VpnDevice.user_id`). Never add ORM `relationship()`/FK across domains. `app/models.py` is the ORM-only registry (imported for side effects by app, worker, alembic env) — register every new domain model module there.
- **Worker**: `arq app.worker.WorkerSettings` (own container). `startup(ctx)` builds the `WorkerCtx` dependency graph; task adapters read from `ctx`, never import providers/repos directly.
- **Repos are persistence-only; never read SQLAlchemy `rowcount`** (unreliable across drivers) — count via `RETURNING` CTE + secondary SELECT. Never use `assert` for runtime control flow/validation.
- **Auth quirks (intentional, don't "fix")**: `is_verified` gates invoice creation only — unverified users can log in and use sessions. Node-agent steady-state endpoints (`/v1/control-plane/`) use short-lived JWTs in `Authorization: Bearer`; bootstrap endpoints use per-server Bearer secrets.
- **Pre-commit** (`.pre-commit-config.yaml`): ruff (check excludes `backend/alembic/`), pyright, lint-imports, gofmt+golangci-lint (node-agent and boltmeshd), eslint, dart format + flutter analyze, terraform fmt/validate, packer validate, prettier, markdownlint.
- IGNORE `infra/.env` — no real secrets.
- Do not implement backward compatibility, there is no production servers yet.
- Try to not overengineer, keep it simple, guard only real edge cases, no redundant checks.
